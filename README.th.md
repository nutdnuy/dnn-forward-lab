# DNN Forward Lab — คู่มือภาษาไทย

โปรเจกต์วิจัยนี้นำแนวคิดจาก [DNN-ForwardTesting (2022)](https://arxiv.org/abs/2210.11532) มาทำเป็นเครื่องมือ Python ที่ทดลองซ้ำและตรวจสอบย้อนหลังได้ ใช้ DNN สร้างเส้นทางราคาอนาคต แล้วเลือกกลยุทธ์จากเส้นทางนั้น ก่อนประเมินกับราคาที่เกิดขึ้นจริง

**เป็นการพัฒนาจากแนวคิดในงานวิจัย ไม่ใช่การยืนยันว่าทำซ้ำผลตัวเลขในบทความได้** ตัวอย่างใช้ราคาสังเคราะห์ ไม่ใช่ข้อมูลตลาด และใช้ตรวจการทำงานของซอฟต์แวร์เท่านั้น

## เริ่มใช้งาน

ติดตั้ง Python 3.12 และ [uv](https://docs.astral.sh/uv/getting-started/installation/) แล้วรัน:

```bash
git clone https://github.com/nutdnuy/dnn-forward-lab.git
cd dnn-forward-lab
uv sync --frozen --python 3.12
uv run --frozen dnn-forward demo --output runs/first-demo
```

เปิด `runs/first-demo/report.html` ในเบราว์เซอร์ บน Mac ใช้ `open runs/first-demo/report.html` ได้ รายงานมีกราฟ ผลเปรียบเทียบ ข้อจำกัด และสมมติฐานครบในไฟล์เดียว ใช้งานออฟไลน์ได้หลังติดตั้ง

ใช้โฟลเดอร์ผลลัพธ์ใหม่ทุกครั้ง ระบบไม่เขียนทับการทดลองเดิม

## สิ่งที่ระบบทำ

1. ตรวจข้อมูล OHLC โดยไม่เติมค่าหรือซ่อมราคาจริงเงียบ ๆ
2. แบ่งข้อมูลตามเวลา ฝึกโมเดล 4 ชุดสำหรับ Open, High, Low, Close
3. พยากรณ์ต่อเนื่อง 30 แท่ง ใช้ค่าพยากรณ์เองเป็นอินพุตถัดไป ไม่ใช้ราคาจริงในอนาคต
4. เลือกจาก 15 กลยุทธ์ แล้วเทียบกับวิธีเลือกจากอดีต, Buy and Hold ที่เริ่มใหม่แต่ละช่วง และถือเงินสด
5. คิดค่าธรรมเนียมและ slippage ทั้งขาซื้อและขาย ใช้สัญญาณหลังปิดตลาด ส่งคำสั่งที่ราคาเปิดวันถัดไป
6. บันทึกการตัดสินใจ ราคาเข้าออก ต้นทุน เงินสด หุ้น และผลตอบแทนให้ตรวจสอบซ้ำได้

## ใช้ข้อมูลจริง

เตรียม CSV หนึ่งหุ้นต่อไฟล์ มี `date,open,high,low,close` และ `volume` ถ้ามี วันที่ใช้ `YYYY-MM-DD` เรียงจากเก่าไปใหม่ ทุกคอลัมน์ราคาต้องปรับ corporate action แบบเดียวกัน ห้ามใช้ Adjusted Close ปนกับ OHLC ที่ยังไม่ปรับ

```bash
uv run --frozen dnn-forward validate data/ANF.csv
uv run --frozen dnn-forward run \
  --csv data/ANF.csv --asset ANF \
  --source "Provider name; snapshot YYYY-MM-DD" \
  --adjustment "Describe consistent OHLC adjustment" \
  --config configs/research.toml \
  --output runs/anf-research
```

เปลี่ยนแหล่งข้อมูลและวิธีปรับราคาให้ตรงของจริง ค่าใน `research.toml` ต้องการอย่างน้อย 864 แท่ง: 504 แท่งเป็นประวัติเริ่มต้น แล้วประเมิน 12 ช่วง ช่วงละ 30 แท่ง ข้อมูลส่วนเกินท้ายไฟล์จะรายงานว่าไม่ได้ใช้

## อ่านผลอย่างไร

- `report.html`: รายงานสำหรับอ่านและเปรียบเทียบ
- `summary.json`: ผลรวมและผลแต่ละช่วง
- `daily_returns.csv`: ผลตอบแทนรายวันของทุกวิธีในวันเดียวกัน
- `fold_XX/selection.json`: คะแนนของทุกกลยุทธ์ก่อนเลือก
- `fold_XX/training.json`: ช่วงฝึก/ตรวจสอบและค่าความผิดพลาด
- `fold_XX/*_orders.csv`: วันของสัญญาณ ราคาเติมคำสั่ง และต้นทุน
- `manifest.json`: การตั้งค่า เวอร์ชันไลบรารี ลายนิ้วมือข้อมูล/โค้ด และสถานะเสร็จสมบูรณ์

`Undefined` หรือ `null` หมายถึงคำนวณอัตราส่วนนั้นไม่ได้ เช่น ไม่มีความผันผวนหรือไม่มีขาดทุน ไม่ได้แปลว่าเป็นศูนย์

ดูจำนวน **forecast candle repairs** ด้วย โมเดลอาจทำนายผิดเงื่อนไข เช่น High ต่ำกว่า Close ระบบปรับเฉพาะราคาพยากรณ์และรายงานจำนวนครั้ง การปรับบ่อยบ่งชี้ว่าโมเดลยังไม่น่าเชื่อถือ แม้ผลเลือกกลยุทธ์ในตัวอย่างเป็นบวก

## ขอบเขต

ยังไม่มีผลยืนยันจาก ANF/EOG ชุดเดียวกับต้นฉบับ ไม่มี Prophet และไม่มีระบบส่งคำสั่งจริง ผลสังเคราะห์ไม่ใช่หลักฐานว่ากลยุทธ์ทำกำไรในตลาดได้ อ่าน [วิธีทดลอง](docs/METHODOLOGY.md) และ [แผนที่อ้างอิง](docs/SOURCE_MAP.md) ก่อนต่อยอด
